Styxpress

A local static blog engine for Markdown sites. Edit on your machine, render public files ahead of time, publish over SFTP, and serve the site with a simple static web server.

Why Styxpress

Author locally. Ship static files.

Styxpress keeps the editor and publishing workflow local, while the reader-facing site stays cheap, cacheable, and easy to serve.

MD

Markdown source files

Posts live as plain files under content/posts/{slug}/, with metadata, covers, and post-local assets beside the source.

UI

Local admin UI

Run the distributed admin binary, open the local URL, and manage sites, configuration, styles, posts, featured entries, and publishing.

HTML

Static rendering

Published posts render into public/ along with the homepage, RSS feed, sitemap, CSS, covers, and assets.

SSH

SFTP publishing

Upload generated public files to your server. In server-backed mode, Styxpress can also upload the source content/ directory.

SHA

Remote verification

Compare local public output with the remote public directory using file size and SHA-256 hashes, then see clear publish-state badges.

0DB

No public database

The production site is just files served by Caddy, Nginx, or another static server. No public CMS process is required for readers.

Pipeline

One local workflow, one static output directory.

Styxpress separates authoring from serving. The admin binary handles editing and publishing; the public server serves only generated files.

Run the admin binary

Start ./styxpress-admin. It binds to loopback by default and prints a local URL for the embedded admin UI.

Render locally

Save Markdown and site settings under content/. Published posts render into public/.

Publish and verify

Upload static files over SFTP, then compare local and remote output to see what is published, missing, or changed.
